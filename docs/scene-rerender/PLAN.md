## 1. 왜 "후처리 재렌더"인가 — 확인된 기술적 근거

ai-video 파이프라인을 조사한 결과, **완성된 job 디렉토리를 후처리해서 재렌더하는 구조**가 최소 변경으로 가능하다:

| 현지화 대상 | 산출물/코드 위치 | 확인된 사실 |
|---|---|---|
| 대사 자막 | `subtitle_segments.json` | `--from-step render` 재렌더 시 `.ass`를 **이 파일에서 재생성**한다(`ai-video/app/pipeline.py:2919-2921` — segments 캐시 재로딩 → `build_ass_from_segments`). 즉 이 파일의 `text`만 일본어로 바꾸면 일본어 자막이 번인된다 |
| 상단 제목(번인) | `edit_plan.json` → `layout.top_title` | 렌더가 `edit_plan["layout"]["top_title"]`을 읽는다(`pipeline.py:2466`). 파일 수정 → 재렌더로 교체 가능 |
| 하단 밴드 작품명 | `--title` 인자 | 혜미리예채파는 `branding` 로고가 없어 작품명 **텍스트**를 밴드에 렌더한다. 재렌더 시 `--title "ヘミリイェチェパ"`를 주면 밴드만 일본어가 된다. `--job-id` 지정 시 디렉토리는 job_id로 찾으므로(`pipeline.py:1462-1466`) 제목이 달라도 디렉토리가 새로 생기지 않는다 |
| TTS 자막 | tts cue (checkpoint) | TTS **오디오는 한국어 유지**(범위 밖), cue 텍스트만 일본어로 바꾸면 TTS 자막이 일본어로 재생성된다(`pipeline.py:2948-2963`) |
| 재렌더 진입점 | `create_shorts --from-step render --job-id <id>` | loudness A/B에서 이미 검증된 경로(`ai-video/app/cli.py:71`) |
| 유튜브 제목/설명 | `scripts/publish_youtube.py` | `--title` 인자로 제목 오버라이드 가능(`publish_youtube.py:341,361`). 설명란은 `build_snippet`이 조립 |

**대안 비교** — ① 생성 단계부터 일본어로(Gemini 프롬프트 언어 변경): ai-video 코어 수정 범위가 크고 한국 채널과 코드 경로가 갈라진다. ② 완성 mp4 위에 자막 오버레이: 한국어 자막이 이미 번인돼 있어 이중 자막이 된다. → **③ 후처리+재렌더 채택**: ai-video 코드는 안 건드리고, job 디렉토리의 데이터 파일만 바꿔 렌더만 다시 돈다.

## 2. 프로젝트 구조

위치: `~/ves/video-localization-project` (brain·ai-video와 형제. venv는 ai-video 것 공용).

```
video-localization-project/
├── PLAN.md                      # 이 문서
├── config/
│   └── locales.json             # 채널→로케일, 작품 일본어 표기, 용어집(멤버명 등), 메타 템플릿
├── scripts/
│   ├── localize_run.py          # 메인 CLI: job 디렉토리 하나를 통째로 현지화
│   ├── translate_segments.py    # L1 대사 번역
│   ├── extract_onscreen.py      # L2 화면 내 한글 추출+번역 (Gemini 영상 패스)
│   └── localize_metadata.py     # L5 유튜브 제목·설명·태그
└── results/
    └── localize_state.json      # run별 처리 상태 (원본 백업 경로 포함)
```

### 파이프라인 단계 (`localize_run.py --job-dir <run> --locale ja`)

```
L0 수집·백업   job 디렉토리에서 subtitle_segments.json · edit_plan.json · title.txt ·
               checkpoint(tts cue) 를 읽고, 원본을 <run>/localize_backup_ko/ 에 백업
L1 대사 번역   subtitle_segments 전체를 문맥째 Gemini 에 넘겨 일본어로 (용어집 강제)
L2 텔롭 추출   shorts.mp4(≈60s) 를 Gemini 3.1 Pro 에 영상 입력 → 화면에 박힌 한글
               텍스트를 타임스탬프·위치와 함께 추출 → 일본어 번역
L3 자막 병합   L1(대사, 하단 스타일) + L2(텔롭, 별도 스타일·상단/원문 근처 배치)
               → subtitle_segments.json 교체 + 텔롭용 세그먼트 추가. 시간·위치 충돌 조정
L4 재렌더     ai-video create_shorts --from-step render --job-id <id>
               --title "ヘミリイェチェパ" + 일본어 폰트 design 플래그
L5 메타       title.txt 번역(=유튜브 제목), 설명란 일본어 템플릿, 태그(일/한 병기)
L6 발행 연계   publish_youtube.py --title <일본어 제목> ... (기존 unlisted → 사람 공개 흐름 유지)
QA            역번역 자기검증 + 용어집 위반 검사 → 통과 못 하면 발행 보류 플래그
```

멱등성: `localize_state.json`에 run별 완료 단계를 기록. 재실행 시 백업본(ko)에서 다시 시작하므로 이중 번역이 없다.

## 3. L1 — 대사 자막 번역 규칙

- **문맥 통번역**: 세그먼트를 한 줄씩 번역하지 않고 전체 대본 + 작품·장면 설명(checkpoint_story의 맥락)을 함께 넘긴다. 예능 대사는 문맥 없이는 오역된다.
- **일본 쇼츠 자막 문체**: 짧은 구어체, 반말/존댓말 구분(멤버 간 관계 반영), 감탄사는 일본식(あ〜, えっ, マジで 등)으로 의역. 직역 금지.
- **용어집(glossary) 강제** — `config/locales.json`에 두고 프롬프트에 주입 + 사후 검사:
  - 작품명: 혜미리예채파 → **ヘミリイェチェパ** (채널 설명 기존 표기)
  - 멤버명(공식 표기 확인 후 확정): 혜리→ヘリ, 미연→ミヨン, 리정→リジョン, 예나→イェナ, 채원→チェウォン, 파트리샤→パトリシア ※확정 전 반드시 일본 공식/통용 표기 검증
  - 프로그램 고유 코너명·유행어는 처음 등장 시 결정해 용어집에 누적
- 길이 제약: 일본어는 한국어보다 길어지기 쉽다. 세그먼트당 2줄·줄당 전각 13~15자 목표로 압축 의역(현행 .ass가 2줄 래핑 구조).

## 4. L2 — 화면 내 한글(텔롭) 처리

- **추출**: 완성 shorts.mp4를 Gemini 3.1 Pro(이 레포 모델 규칙상 Pro 고정)에 넣어 "화면에 렌더된 한글 텍스트"를 `{start, end, text, 위치(상/중/하), 종류(방송자막/뉴스바/소품)}`로 뽑는다. 60초 영상 1편이라 비용·시간 부담 없음.
- **선별**: 모든 한글을 다 번역하지 않는다 — ① 내용 이해에 필요한 방송 텔롭은 번역, ② 배경 간판·소품 등 이해와 무관한 글자는 생략, ③ 이미 대사 자막과 같은 내용이면 생략(이중 표기 방지).
- **표기 방식**: 원본 텔롭 **근처에 일본어 병기** 스타일(작은 폰트, 반투명 배경 박스, 대사 자막과 다른 색). 대사 자막(하단)과 영역 충돌 시 상단으로 밀어낸다.
- **한계 명시**: 원본 한글을 지우는 인페인팅은 범위 밖(병기 방식). 텔롭이 많은 장면은 QA에서 사람이 확인.

## 5. 제목·작품명·설명란 규칙

- **유튜브 제목**: `title.txt`(예: "상하체 분리 댄스 하더니 결국 고장 나버린 미연")를 일본 쇼츠 어법으로 의역 + 권리사 가이드 "쇼츠 제목에 작품 제목 삽입" 준수 → 제목에 `ヘミリイェチェパ` 포함. 예: `上半身と下半身が別人ダンスで壊れたミヨンw【ヘミリイェチェパ】`
- **번인 상단 제목**: 유튜브 제목과 별개로 `edit_plan.layout.top_title`을 일본어로(줄바꿈 2줄 구조 유지).
- **설명란**: 일본어 본문 + 태그. ⚠️ 권리 고지 "채널 ENA에서 시청 가능"은 **한국어 원문 유지 + 일본어 병기**(`チャンネルENAで視聴可能`)를 기본으로 한다 — 가이드가 요구하는 건 원문 문구라서 번역만 남기면 준수 여부가 애매해진다. 권리사에 일본어 단독 표기 가능 여부 확인 후 완화(§9).
- **해시태그**: laeebly `required_hashtags`(한국어)는 그대로 두고 일본어 태그(`#ヘミリイェチェパ #韓国バラエティ` 등, channels.json keywords 재활용)를 추가.
- 🛑 **내부 키는 절대 일본어로 바꾸지 않는다**: works.json 키·channels.json `works`·DB `works.title`은 "혜미리예채파" 유지. 작품명은 발행 시 laeebly 완전일치 조회 키라서(brain CLAUDE.md §1-3 경고) 일본어로 바꾸면 권리 조회가 통째로 실패한다. **일본어는 표시 계층에서만.**

## 6. 폰트

- 현행 자막 폰트 `Jalnan Gothic TTF`(여기어때 잘난체)는 한글 전용 — 일본어 글리프(かな·한자) 커버리지 확인 필요. **잘난체는 일본어판(ジャルナン体)이 없으므로** 대체 폰트를 정한다.
- 후보(상업적 무료·예능 텔롭 느낌): ① 케이폰트(けいふぉんと) ② M PLUS Rounded 1c ③ Noto Sans JP Black(안전 기본값). 제목/밴드용은 굵은 웨이트.
- ai-video는 `--design-title-font` 등 design 플래그로 폰트 지정 가능(`cli.py:109`) — 재렌더 시 플래그로 주입, 폰트 파일은 ai-video `app/assets` 규약에 맞춰 설치.

## 7. 운영 통합 — scene_loop과의 관계

- 배정: ショトコン 담당은 이 머신(macmini-luna3). 로컬라이즈도 같은 머신에서 돈다(진행 상태 파일이 머신별이라는 기존 원칙 유지).
- **훅 위치**: scene_loop 생성 완료 후 ~ 발행 전. 초기(Phase 1)에는 사람이 `localize_run.py`를 수동 실행. 안정화(Phase 2) 후 scene_loop에 "channel country==JP면 localize 완료를 발행 전제로 요구"하는 게이트 한 줄을 추가(브레인 레포 수정 최소화).
- 발행은 기존 흐름 그대로: unlisted 업로드 → **사람이 검수 후 공개**(기존 브레이크 유지 — 초기에 일본어 품질 검수를 이 지점에서 같이 한다).
- 현재 ショトコン은 EP1 **미공개 대기 3편**(2026-08-03 루프 로그: `혜미리예채파_74` 등)이 쌓여 생성이 멈춰 있다 → **이 3편이 시범(파일럿) 대상**. 이미 unlisted로 올라간 편이 있으면 재업로드가 아니라 메타데이터 수정 + 영상 교체 불가 문제가 있으므로, **아직 미업로드분은 현지화 후 업로드**, 이미 업로드분은 소급 여부를 §9에서 결정.

## 8. Phase 0 — 스파이크 ✅ 완료 (2026-08-04)

**전 항목 통과 — 결과·설계 수정 사항은 `SPIKE_RESULTS.md` 가 정본.** 핵심 변경 요약:
- 상단 제목 정본은 `checkpoint_story.json variants[].title_text` (edit_plan 은 폴백) — 둘 다 수정.
- 재렌더는 원본 gen_flags(`loop_policy.json gen_flags_base`) 반복 필수 — 아니면 컷이 달라져 자막 싱크가 깨진다(실증: 49.7s→53.3s).
- 원본 ショトコン 쇼츠는 `--no-subtitles`(오자막 방지) — 일본어판은 자막을 켜는 정책 예외. 텔롭 추출(L2)을 먼저 돌려 그 원문으로 대사(L1)를 교정-번역한다(Whisper "멀티 그룹/그루브" 오청취를 텔롭이 교정한 실증).
- 자막 폰트 CLI 플래그가 없음 → Phase 1 에서 ai-video `--design-subtitle-font` 추가 필요.
- 편당 오버헤드 실측: 재렌더 51.5초(캐시 웜) + Gemini 2콜(~1분).
